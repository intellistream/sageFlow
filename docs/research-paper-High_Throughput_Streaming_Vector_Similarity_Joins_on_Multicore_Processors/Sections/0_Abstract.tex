\begin{abstract}
Vector similarity joins are a core primitive for modern embedding-centric analytics, yet most prior multicore studies target static or batched data where index construction and partitioning costs can be amortized offline. Streaming workloads are harder: tuples arrive continuously, window contents evolve rapidly, expired tuples must be removed safely, and parallel workers contend on shared state under strict latency budgets. We present \system, a multicore streaming vector join mechanism implemented in \sageflow, that combines a strategy-driven join runtime with a VSJoin-oriented execution path. The design uses a partitioned two-tier indexing layout (global index for broad candidate recall and partition-local indexes for write-efficient ingestion), vector-space partitioning to improve locality and reduce synchronization, and boundary-aware multicast routing for vectors near partition borders. At query time, candidate retrieval and verification are separated: local/global indexes generate candidates, while window and similarity predicates validate final join outputs under sliding-window semantics. The system integrates multiple baselines (BruteForce, IVF, HNSW, HDR-Tree, LSH, ClusteredJoin, and S3J-style methods) in the same execution framework, enabling controlled end-to-end comparison. Experiments on representative streaming workloads show competitive throughput--latency trade-offs and robust join quality across window sizes and similarity thresholds, while highlighting the practical constraints required for stable high-parallel execution.
\end{abstract}
