\begin{abstract}
Vector similarity joins are a core primitive for modern embedding-centric analytics, yet most prior multicore studies target static or batched data where index construction and partitioning costs can be amortized offline. Streaming workloads are harder: tuples arrive continuously, window contents evolve rapidly, expired tuples must be removed safely, and parallel workers contend on shared state under strict latency budgets. We present \system, a multicore streaming vector join mechanism implemented in \sageflow, that combines a strategy-driven join runtime with a VSJoin-oriented execution path. The design uses a partitioned two-tier indexing layout (global index for broad candidate recall and partition-local indexes for write-efficient ingestion), LSH-based boundary-aware multicast routing, and logical-partition indirection ($P\times V$) mapped via an RCU-style assignment table. For robustness under skew, \system couples sampled load telemetry (interval record deltas with EWMA-smoothed backlog/latency signals) with threshold-triggered, bounded logical-partition remapping. For correctness under asynchronous maintenance, global index refresh is driven by snapshot event-time maxima rather than wall-clock ticks, reducing stale/empty rebuild artifacts in sparse windows. At query time, candidate retrieval and verification are separated: local/global indexes generate candidates, while window and similarity predicates validate final join outputs under sliding-window semantics. The system integrates multiple baselines (BruteForce, IVF, HNSW, HDR-Tree, LSH, ClusteredJoin, and S3J-style methods) in the same execution framework, enabling controlled end-to-end comparison. Experiments on representative streaming workloads show competitive throughput--latency trade-offs and robust join quality across window sizes and similarity thresholds, while highlighting practical constraints of periodic, heuristic rebalancing for stable high-parallel execution.
\end{abstract}
